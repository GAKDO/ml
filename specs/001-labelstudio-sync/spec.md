# 기능 명세: ML3 Label Studio 연동

**기능 브랜치**: `claude/project-thread-sy1p9l` (Spec Kit 기본값은 `feature/001-labelstudio-sync`)

**작성일**: 2026-11-02

**상태**: 초안

**입력**: 백로그 ML3 설명: "Label Studio가 MinIO trace-raw 원본을 작업으로 가져오고(프록시 모드), 주석(폴리곤 4클래스)을 trace-labels에 쓴다(FR-DAT-03). 수용 기준: 새 사진이 동기화 한 번에 작업으로 뜬다. 원본 사진은 바뀌지 않는다."

**요구사항 ID**: FR-DAT-03

## 명확화

### 세션 2026-11-02

- Q: Label Studio 설정은 화면에서 손으로 하나요, 스크립트로 하나요? → A: 같은 설정을 몇 번이고 다시 만들 수 있게 명령 하나(`trace-ml labelstudio setup`)로 한다. 이미 있으면 고치지 않고 그대로 쓴다
- Q: SLATE(ID 카드) 사진도 작업으로 가져오나요? → A: 가져오지 않는다. `trace-raw/{기기ID}/` 바로 아래의 면 사진만 가져오고 `slate/`는 뺀다
- Q: 흠집이 없는 사진은 어떻게 표시하나요? → A: "흠집 없음"(no_defect) 체크로 표시한다. 체크도 폴리곤도 없는 제출은 빌더(ML1)가 오류로 막는다(킥오프 계획)

## 사용자 시나리오와 테스트 *(필수)*

### 사용자 스토리 1 - 촬영한 사진이 라벨링 작업으로 뜬다 (우선순위: P1)

라벨러는 Label Studio의 TRACE 프로젝트를 연다. 촬영 도구가 `trace-raw`에 올린 면 사진이 동기화 한 번에 작업으로 보이고, 사진마다 흠집 4종(긁힘·찍힘·균열·오염)을 폴리곤으로 그리거나 "흠집 없음"을 체크해 제출한다.

**우선순위 이유**: 학습 데이터(ML1)와 부스 탐지(BO2)가 모두 이 주석에 기대고 있다.

**독립 테스트**: 가짜 Label Studio API로 설정·동기화를 돌려, 프로젝트·라벨 설정·소스 스토리지가 만들어지고 동기화가 한 번 호출되는지 확인한다.

**수용 시나리오**:

1. **주어진 상황** 프로젝트가 없을 때, **동작** setup을 실행하면, **결과** 폴리곤 4클래스와 "흠집 없음" 체크가 있는 TRACE 프로젝트가 생기고, `trace-raw` 소스와 `trace-labels` 타깃이 연결된다.
2. **주어진 상황** 이미 설정된 상태에서, **동작** setup을 다시 실행하면, **결과** 프로젝트·스토리지가 하나씩만 있다.
3. **주어진 상황** `trace-raw`에 새 사진이 올라왔을 때, **동작** sync를 한 번 실행하면, **결과** 소스 스토리지 동기화가 호출되고 작업 수가 늘어난 만큼 보고된다.
4. **주어진 상황** 소스 스토리지 설정을 보면, **결과** 사전 서명 URL을 쓰지 않는 프록시 모드이고, 면 사진 파일명 규칙에 맞는 키만 가져온다(SLATE 제외).

---

### 사용자 스토리 2 - 주석이 저장소에 쓰이고 원본은 그대로다 (우선순위: P1)

제출된 주석은 `trace-labels`에 쓰이고, 원본 사진(`trace-raw`)은 바뀌지 않는다.

**독립 테스트**: 가짜 API로 export-sync를 호출해 타깃이 `trace-labels`이고 삭제 권한이 꺼져 있는지, 어떤 경로로도 `trace-raw`에 쓰는 설정을 만들지 않는지 확인한다.

**수용 시나리오**:

1. **주어진 상황** 주석이 제출되었을 때, **동작** sync를 실행하면, **결과** 타깃 스토리지 동기화가 호출된다.
2. **주어진 상황** 소스와 타깃 버킷을 같게 설정하면, **결과** setup이 시작하지 않고 오류를 낸다.
3. **주어진 상황** 타깃 스토리지 설정을 보면, **결과** 저장소 객체를 지우는 옵션이 꺼져 있다.

### 경계 상황

- Label Studio에 닿지 않거나 토큰이 틀리면 무엇이 실패했는지 알리고 0이 아닌 코드로 끝난다(토큰 값은 출력하지 않음).
- 같은 이름의 프로젝트가 둘 이상이면 고르지 않고 멈춘다.
- 이미 있는 프로젝트의 라벨 설정이 다르면 덮어쓰지 않고 차이를 알린다(주석이 있는 프로젝트의 설정을 바꾸면 기존 주석이 깨질 수 있음).

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: `setup`은 TRACE 프로젝트, `trace-raw` 소스 스토리지, `trace-labels` 타깃 스토리지를 없을 때만 만들고, 있으면 그대로 쓴다.
- **FR-002**: 라벨 설정은 폴리곤 4클래스(contracts `codes.yaml` 0.3.0 `inspection.defect_class`: scratch·dent·crack·stain)와 "흠집 없음"(no_defect) 체크다.
- **FR-003**: 소스 스토리지는 프록시 모드(사전 서명 URL 끔)이고, 키 필터는 `{기기ID}/{면 사진 파일명}`(booth `contracts/storage-layout.md`)이다.
- **FR-004**: 타깃 스토리지는 `trace-labels`이고 객체 삭제를 허용하지 않는다. 소스와 타깃 버킷이 같으면 거절한다.
- **FR-005**: `sync`는 소스 동기화와 타깃 동기화를 한 번씩 호출하고, 동기화 전후 작업 수를 보고한다.
- **FR-006**: 주소·토큰·MinIO 키는 환경 변수로 받고 출력·로그에 값을 남기지 않는다.

### 핵심 데이터

- **프로젝트**: 제목, 라벨 설정(XML)
- **소스 스토리지**: 버킷 `trace-raw`, 키 필터, 프록시 모드
- **타깃 스토리지**: 버킷 `trace-labels`, 삭제 금지

## 성공 기준 *(필수)*

- **SC-001**: 새 사진이 동기화 한 번에 작업으로 뜬다.
- **SC-002**: 원본 사진이 바뀌지 않는다(쓰기 경로가 없음).
- **SC-003**: setup을 여러 번 실행해도 프로젝트·스토리지가 하나씩만 있다.

## 가정

- Label Studio 1.19.0은 gitops가 클러스터에 띄운다(A). 이 기능은 그 위의 설정과 동기화만 한다.
- Label Studio 접근 토큰은 관리자가 화면에서 만들어 환경 변수로 준다.
- Label Studio가 쓰는 MinIO 키는 킥오프 계획의 labelstudio 역할(trace-raw 읽기, trace-labels 쓰기)이다. 키 이름은 trace-secrets에 정해지면 맞춘다.
- 2차 라벨링의 모델 미리 표시(ML backend)와 SAM은 범위 밖이다.
