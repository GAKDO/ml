## 명확화

### 세션 2026-11-02

(민서가 "묻지 말고 진행"을 요청해, 설계서·킥오프 계획에 맞는 답을 골라 적었다. decisions.md 11/2 "ML1")

- Q: 데이터셋 버전에 사진을 복사하나요? → A: 복사하지 않는다. `trace-datasets/<버전>/`에는 라벨 파일·`data.yaml`·`manifest.json`만 두고, 사진은 `trace-raw` 키와 SHA-256으로 가리킨다. 학습 때 받으면서 해시를 대조해, 원본이 바뀌었으면 멈춘다
- Q: 기기를 어느 분할에 넣는지 누가 정하나요? → A: 사람이 `trace-ml dataset device add <기기> --split TEST`로 먼저 정할 수 있고, 정하지 않은 기기는 빌드 때 기기 수 기준 TRAIN 70%·VAL 15%·TEST 15%에 가장 모자란 쪽으로 자동 배정한다. 배정은 `ml.dataset_device`에 남고, 한 번이라도 버전에 쓰인 기기의 분할은 바꿀 수 없다
- Q: "제출된 주석"은 무엇인가요? → A: `trace-labels`에 내보내진 주석 중 건너뛰기(was_cancelled)가 아닌 것. 초안(draft)은 내보내지지 않는다. 한 사진에 주석이 여럿이면 ground truth, 없으면 가장 최근 것을 쓴다
- Q: 폴리곤도 "흠집 없음"도 없는 제출, 둘 다 있는 제출은? → A: 빌드를 멈추고 해당 작업 번호를 모두 보여 준다(ML3 명확화). 버전은 만들어지지 않는다
- Q: 버전 이름은? → A: `v001`, `v002`…. 지정하지 않으면 다음 번호. 이미 있는 이름(DB 또는 버킷)이면 거절한다
- Q: 학습 기록은 어디에? → A: 파일은 `trace-models/<데이터셋 버전>/<실행 이름>/`(best.pt·best.onnx·metrics.json·run.json), 행은 `ml.training_run`(데이터셋 버전 외래 키). 객체 메타데이터에도 데이터셋 버전을 적는다

## 사용자 시나리오와 테스트 *(필수)*

### 사용자 스토리 1 - 제출된 주석으로 데이터셋 버전을 만든다 (우선순위: P1)

A가 집 PC에서 `trace-ml dataset build`를 실행하면, `trace-labels`의 제출된 주석만 모아 기기 단위로 나눈 YOLO 분할 데이터셋 버전이 `trace-datasets`에 생기고 `ml.dataset_version`에 기록된다.

**독립 테스트**: 가짜 저장소(메모리 S3)와 메모리 기록부로 빌드해, 라벨 파일·manifest·기록 행을 확인한다.

**수용 시나리오**:

1. **주어진 상황** 기기 3대의 제출된 주석이 있을 때, **동작** build를 실행하면, **결과** 한 기기의 사진은 모두 한 분할에만 있고 manifest의 기기→분할 표와 같다.
2. **주어진 상황** 건너뛴 주석이 섞여 있을 때, **동작** build하면, **결과** 그 사진은 데이터셋에 없다.
3. **주어진 상황** v001이 이미 있을 때, **동작** v001로 다시 build하면, **결과** 거절되고 기존 객체는 그대로다.
4. **주어진 상황** 버전을 정하지 않았을 때, **동작** build하면, **결과** 다음 번호(v002)로 만든다.
5. **주어진 상황** 빈 제출(폴리곤·흠집 없음 둘 다 없음)이 있을 때, **동작** build하면, **결과** 작업 번호를 알리며 실패하고 아무것도 쓰지 않는다.
6. **주어진 상황** 기기가 v001에 TEST로 쓰였을 때, **동작** 그 기기를 TRAIN으로 바꾸려 하면, **결과** 거절된다.

### 사용자 스토리 2 - 학습 결과를 데이터셋 버전과 함께 저장한다 (우선순위: P1)

A가 `trace-ml train v001`을 실행하면, 데이터셋을 받아 해시를 대조하고 YOLO11-seg로 학습한 뒤 가중치·ONNX·지표를 `trace-models`에 올리고 `ml.training_run`에 데이터셋 버전과 함께 기록한다.

**독립 테스트**: 학습 함수를 가짜로 바꿔 끼우고, 받기·올리기·기록을 확인한다.

**수용 시나리오**:

1. **주어진 상황** v001이 있을 때, **동작** train하면, **결과** `trace-models/v001/<실행>/`에 best.pt·best.onnx·metrics.json·run.json이 있고, run.json과 객체 메타데이터에 v001과 manifest 해시가 있다.
2. **주어진 상황** 학습이 끝났을 때, **동작** `trace-ml models list`를 보면, **결과** 모델마다 데이터셋 버전이 보인다.
3. **주어진 상황** `trace-raw` 사진 하나가 바뀌었을 때, **동작** train하면, **결과** 학습 전에 멈추고 바뀐 키를 알린다.
4. **주어진 상황** 없는 버전으로, **동작** train하면, **결과** 실패한다.

### 경계 상황

- 라벨 파일에 이미지 키가 파일명 규칙(ML3 키 필터)에 맞지 않으면 빌드를 멈춘다.
- 클래스가 codes.yaml `inspection.defect_class` 밖이면 빌드를 멈춘다.
- 점이 3개 미만인 폴리곤은 멈춘다. 좌표는 0~1로 자른다.
- 작업 트리가 더러우면(커밋 안 된 변경) 빌더 커밋을 믿을 수 없어 `--allow-dirty` 없이는 멈춘다.
- DB·MinIO에 닿지 않으면 무엇이 실패했는지 알리고 0이 아닌 코드로 끝난다(비밀 값은 출력하지 않음).

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 빌더는 `trace-labels`의 내보낸 주석(작업 형식·주석 형식 모두)을 읽고, 건너뛴 주석은 버린다.
- **FR-002**: 각 사진의 기기는 `trace-raw` 키의 첫 경로(기기 ID)로 정하고, 기기의 분할은 `ml.dataset_device` 하나로 정한다(한 기기 = 한 분할).
- **FR-003**: 결과는 YOLO 분할 형식(`labels/{train,val,test}/*.txt`, 클래스 번호 + 0~1 좌표)과 `data.yaml`, `manifest.json`(사진 키·SHA-256, 라벨 SHA-256, 기기 표, 클래스, 개수, 빌더 커밋, codes 버전)이다.
- **FR-004**: 같은 버전 이름은 DB 고유 제약과 버킷 접두사 확인, `If-None-Match: *` 조건부 쓰기로 덮어쓰지 못한다.
- **FR-005**: 검증 오류가 하나라도 있으면 아무것도 쓰지 않는다.
- **FR-006**: 학습은 manifest의 사진을 받아 해시를 대조한 뒤 Ultralytics YOLO11-seg로 돌리고, TEST 분할 지표도 잰다.
- **FR-007**: 학습 결과(best.pt·best.onnx·metrics.json·run.json)는 `trace-models/<버전>/<실행>/`에 덮어쓰기 없이 올리고 `ml.training_run`에 기록한다.
- **FR-008**: 주소·키·DB 비밀번호는 환경 변수로 받고 출력하지 않는다.

### 핵심 데이터

- **dataset_device**: 기기 코드, 기종 이름, 색, 분할
- **dataset_version**: 버전, manifest 키, 빌더 커밋, 개수(jsonb), 만든 시각
- **training_run**: 데이터셋 버전, 기본 가중치, 지표(jsonb), 모델 키, ONNX 키

## 성공 기준 *(필수)*

- **SC-001**: 한 기기가 두 분할에 동시에 없다(빌드마다 검사).
- **SC-002**: 같은 버전을 덮어쓸 수 없다.
- **SC-003**: 모델마다 학습 데이터 버전을 추적할 수 있다(`models list`, run.json, 객체 메타데이터).

## 가정

- `ml` 스키마는 gitops init-db.sh가 만든다. 테이블은 `trace-ml db init`이 docs db/V1__init.sql의 ml 절 그대로 만든다.
- 집 PC는 `kubectl -n trace port-forward svc/postgres 5432:5432`로 DB에 붙는다.
- MinIO 키는 킥오프 계획의 trainer 역할(trace-raw·trace-labels 읽기, trace-datasets·trace-models 쓰기)이다. 없으면 팀 키(`MINIO_ACCESS_KEY`)로 대신한다.
- TensorRT 엔진은 Jetson이 ONNX에서 직접 만든다(BO2). 이 기능은 ONNX까지.
